# SEO Sprint 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the brand/authority leak between the blog and the Anvax site — one
brand in titles/OG/JSON-LD, visible org authorship, structured data, an internal
link graph, and dedicated indexable URLs for the six priority industry verticals.

**Architecture:** Mostly additive — two new presentational components
(`ByLine`, `AuthorBio`), one new content-selection function (`getRelatedPosts`), one
new route family (`/industries/<slug>`, six static pages sharing one shell
component), and a handful of exact-string edits to existing metadata blocks. No
new data source, no new build tooling, no test framework introduced (none exists
in this repo today — verification leans on `tsc`/`build`/manual content checks).

**Tech Stack:** Next.js 15 App Router, `next-mdx-remote/rsc`, `gray-matter`,
TypeScript, CSS Modules.

**Spec:** `docs/superpowers/specs/2026-10-24-seo-sprint-1-design.md`

## Global Constraints

- Tokens only in any `*.module.css` — no raw hex/rgb/px color.
- Square corners (`--radius-*` is `0` except `--radius-chip`/`--radius-pill`).
- No new npm dependency.
- `npx tsc --noEmit` must report 0 errors; `npm run build` must pass, after every task.
- `Team Anvax` is the author everywhere — no personal name, no personal LinkedIn.
- Non-goals (do not implement in this PR): contextual-link backfill into the 27
  existing posts; full content for the 5 non-insurance industry pages beyond the
  placeholder shell; any `/industries` accordion UI redesign beyond the hub links
  in Task 7.

## Blocked on Yogesh — do not guess these

- **`twitter:site` handle.** No Anvax X/Twitter handle exists anywhere in the repo.
  Not implemented in this plan; add it to `src/app/layout.tsx`'s `twitter` block
  (currently absent — each page sets its own `twitter` object with no site-wide
  default) once supplied.
- **Organization `sameAs`.** LinkedIn company page, Substack, Medium, GitHub (if
  public) URLs for `src/components/OrganizationJsonLd.tsx`. Not implemented. Add an
  array of URLs to the `Organization` object's `sameAs` field once supplied.
- **Industries taxonomy mismatch (see Task 7).** The existing `/industries`
  accordion's 6 verticals (`financial-services`, `healthcare`, `legal`,
  `public-sector`, `defence`, `technology`) don't line up with the 6 new SEO page
  slugs (`insurance-brokers-mgas`, `accountancy-audit`,
  `architecture-engineering-construction`, `wealth-asset-management`,
  `legal-professional-services`, `public-sector`) except the one exact match,
  `public-sector`. Task 7 only wires that one match plus the closest conceptual
  pair (`legal` → `/industries/legal-professional-services`) into the accordion's
  "Read more" links and leaves `healthcare`, `defence`, `technology` accordion
  entries unlinked to any new page (they genuinely don't have one). **This is a
  product decision, not an implementation detail** — if the intent is for the six
  new pages to eventually replace the accordion's taxonomy entirely, that's a
  bigger restructure than this sprint and should be scoped separately.

## Review Focus

- The homepage's meta `description` and `openGraph.description` are currently
  **identical strings** — a find-and-replace that only touches one of the two
  silently leaves the site with two different descriptions depending on surface
  (plain search result vs. social-share card). Both occurrences need the new copy.
- `PostFrontmatter.description` is typed as required `string` but read via a plain
  cast with zero runtime check today — a future post that forgets the field
  wouldn't fail *type-checking*, only the new runtime validation this plan adds.
  Confirm the validation actually throws at *build* time (via `getStaticParams`/
  the page's data fetch), not just when a function happens to be called at runtime
  in a dev request.
- The duplicate-H1 fix is confirmed for exactly one post
  (`permission-aware-retrieval-query-time-acls.md`) by manual inspection — treating
  that as the only instance and skipping a full grep of all 25 files would ship
  the same bug in any other post that happens to open with `# <title>`.
- `IndustriesClient.tsx` and `src/app/industries/IndustriesClient.tsx`'s accordion
  items use `<a href>` not `next/link` — the six new industry page links added in
  Task 7 should match that file's existing convention (plain anchors) rather than
  introducing a `next/link` import inconsistently into a file that doesn't use it.
- `sitemap.ts`'s `staticPages` is a flat hand-maintained array — adding six entries
  is easy to get subtly wrong (trailing slash, missing `https://www.anvax.in`
  prefix, wrong `lastModified`) in a way that validates fine in TypeScript but is
  wrong in the actual sitemap XML; diff the rendered `/sitemap.xml` output, don't
  just trust the array literal compiles.
